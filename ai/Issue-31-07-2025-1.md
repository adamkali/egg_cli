# Issue 31/07/2025 1 - Integrating Testing into the CI/CD Pipeline 

## Summary
We want to be able to have a CI/CD pipeline that includes testing, so that we can ensure that the code we are pushing to the repository is working as expected.
You should edit the ./.github/workflows/ci.yml file to add a test step to the build job. And then edit the workflow file so that when building on a the dev branch the tests are ran, the package is built for the existing matrix, then there is an automatic release created. 

## Goals
- make a dev branch that is used for development and testing
- when a pull request is merged into the dev branch, the tests are run and the package is built for the existing matrix, and the minor version x.y.z (minor here is y) is incremented, and released
- when a pull request is merged into the main branch, the tests are run and the package is built for the existing matrix, and the major version x.y.z (major here is x) is incremented

## Before You Start
- Make sure you are up to date with the latest changes in the repository
- Make sure to create a new branch for your work based on the dev branch

## When You Finish
- verify that the build target works by using make build
- Update the Claude.md file to explain to other ai agents the current state of the project, what you have done, and what you believe the project should plan to do next.
- Commit your changes to the repository and explain the changes you made.
- and make a pull request to the dev branch
